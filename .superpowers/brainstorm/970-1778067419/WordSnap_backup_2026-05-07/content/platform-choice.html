关键技术决策：React Native vs Flutter

产品文档中两种方案都列出了，需要选定一个

React Native

优势

  • 共享 Web 生态技能（React 社区庞大）
  • 剪贴板监听、原生模块桥接成熟
  • Expo 生态开箱即用（推送、相机、存储）
  • 未来浏览器插件可复用 React 组件
  • 热更新 OTA（CodePush）

劣势

  • 性能上限低于 Flutter（列表、动画）
  • 原生 OCR 集成需写原生模块（Vision/ML Kit）
  • 跨平台 UI 一致性需额外调试

Flutter

优势

  • 渲染性能强，复杂动画/列表流畅
  • UI 一致性开箱即用（自绘引擎）
  • 内置相机、存储等插件完整
  • Dart 类型安全，编译期错误少

劣势

  • 浏览器插件无法复用代码
  • Dart 生态相对小
  • 学习曲线（团队需掌握 Dart）
  • 第三方 SDK 绑定可能滞后

我的推荐：React Native (Expo)

理由：产品文档提到未来会有浏览器插件（网页剪藏），React 生态可复用组件；Expo 已成熟支持自定义原生模块（Expo Modules API），OCR 集成不再是障碍；剪贴板监听等系统级功能在 RN 生态中实现更自然。

替代思路：先做一个平台？

如果时间有限，是否考虑 MVP 只做 iOS（SwiftUI 原生）？可以利用 iOS Vision OCR 的一流集成，SRS 算法用 Swift 实现，体验最流畅。Android 版本后续跟进。但代价是两套代码、两倍维护。
