仅 Android 端：React Native vs Flutter 成本对比

去掉 iOS 包袱后，两个方案的成本结论会变化

环境搭建难度

React Native + Expo

最简路径（Expo）：

  • 安装 Node.js → npx create-expo-app
  • 手机装 Expo Go，扫码即跑
  • 不需要 Android Studio（初期）
  • 需要原生模块时再装 AS + JDK

搭环境 ≈ 30 分钟

Flutter
  • 安装 Flutter SDK + Dart SDK
  • Android Studio（必装，含模拟器 + SDK）
  • 配置 ANDROID_HOME、PATH 环境变量
  • flutter doctor 排错链路长
  • Windows 上 Gradle 同步偶尔挂

搭环境 ≈ 1-4 小时（看运气）

Android 端开发成本对比

维度 React Native Flutter
OCR（ML Kit） 社区包成熟，需写原生桥接 官方 Google 插件，直接 pub add
相机 expo-camera ✅ camera 插件 ✅
剪贴板 expo-clipboard ✅ super_clipboard ✅
SQLite expo-sqlite ✅ sqflite ✅
本地通知 expo-notifications ✅ flutter_local_notifications ✅
UI 一致性 使用原生组件，需要调 Material Design 原生感觉
动画 & 长列表 有一定性能损失 渲染引擎自绘，流畅
热重载 Fast Refresh ✅ Hot Reload ✅
学习 + 开发效率 JS/TS 通识技能，上手快 Dart 需学习，但文档全

结论：仅 Android 时，Flutter 优势更明显

只做 Android 端，跨平台代码复用不再是优势，纯粹比 Android 开发体验：

  • ML Kit OCR — Flutter 有 Google 官方插件，RN 靠社区维护的桥接包
  • UI 原生感 — Flutter Material Design 对 Android 用户零违和感
  • 性能 — 复习卡片动画、长列表滚动，Flutter 自绘引擎更稳
  • 环境搭建 — RN(Expo) 更简单，但一旦要写原生模块，复杂度追平 Flutter

唯一牺牲：未来浏览器插件无法共享 UI 代码（仍需独立 Web 技术栈开发）。
